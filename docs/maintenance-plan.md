# ProxyAll 维护与扩展计划

## 本轮目标与验收

| 范围 | 实施步骤 | 验收条件 |
| --- | --- | --- |
| XHTTP 节点 | 对照 TLS 与 Reality 的创建、配置导出和链接查看调用方。合并路径、名称、XMUX、ENC 的输入，以及 mihomo 配置和链接的公共字段。证书签发和 Reality 握手各自由对应分支处理。 | 两种模式的默认值、取消返回、专属字段及类型符合已有行为。创建与改端口后导出的链接可解析，mihomo 可通过本地节点收发流量。 |
| 反代签发 | 在每次签发决策开始时查询一次 ACME 记录，使用同一份记录检查证书路径、webroot 与续期钩子。 | 已有 HTTP-01 证书的检查仅调用一次 `--info`。模拟复用、迁移、信息查询失败及无 TLS 场景。 |
| 旧中转导入 | 在解析器和配置写入之间检查退出状态、输出对象数量、协议名、地址、端口。 | 非零退出、非法输出均在调用配置写入前失败。合法链接能进入确认或配置流程。 |
| 组件发布 | 将仓库内的哈希引用集中列在开发工具中，依赖在先、引用方在后。先计算所有改动，再刷新声明。 | 修改临时副本的 `parser.sh` 会识别所有受影响的上游脚本。刷新后二次检查无差异，安装器接受整套脚本。 |
| 独立工具归档 | 将独立安装器移入 `archive/`，在项目约定与检索配置中划定日常维护范围。 | 主安装入口、旧组件下载路径与订阅工具可继续使用，默认 `rg --files` 排除归档目录。 |

## 后续改动的触发条件

1. 新增节点协议时，先从 `_xray_menu` 列出该协议在创建、编辑、端口变更、删除及聚合订阅中的调用点。用一个完整的节点生命周期样例固定预期，再集中相同的类型分派。事务提交和失败回滚继续交给现有节点事务函数。验收覆盖旧节点缺失新增字段及客户端真实导入。
2. 调整旧版 sing-box 兼容范围时，分别盘点直接执行 `sb`、旧菜单 `_main_menu`、迁移命令和定时维护任务可达的函数。兼容测试先使用旧版本配置验证迁移及备份，再移动有明确边界的代码。这一步可以进一步缩小 `sb.sh` 的日常维护范围。
3. 扩展共享 443 或证书策略时，将两端依赖的锁顺序、SNI 所有者及服务重载失败恢复写成契约测试，再判断能否提取公共实现。验收需在独立入口与统一菜单都运行同一组用例，并通过真实 HAProxy 共享入口。
